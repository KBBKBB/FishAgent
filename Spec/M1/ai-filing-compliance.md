# M1-T10 生成式 AI 备案路径咨询（合规）

> 对应 Roadmap §2.2 M1-T10（🔴 高风险，**工期可能很长**）、立项文档 7.4。
> 结论：**🟡 中高风险，但工期远短于「自研大模型备案」——走「轻」通道：大模型登记 + 算法备案（生成合成类）。**
> 依据：《生成式人工智能服务管理暂行办法》（2023-08-15 施行）、《人工智能生成合成内容标识办法》
> （2025-09-01 施行）、《互联网信息服务算法推荐管理规定》、《互联网信息服务深度合成管理规定》，
> 及 2026 年属地网信办实操口径。

---

## 1. 先分清三条路径：备案 / 登记 / 算法备案

《生成式人工智能服务管理暂行办法》确立的是**「备案 + 登记」双轨**，再叠加既有的**算法备案**，
三者**不是二选一，而是各自独立**。选错路径是最大的时间成本来源。

| 义务 | 适用对象 | 审核层级 | 入口 | 常规周期 |
|---|---|---|---|---|
| **大模型备案**（生成式 AI 服务备案） | **自研**底座，或对第三方模型做**预训练 / 优化训练 / 微调（改动权重）**后对外服务 | 省级网信办初审 → **国家网信办终审** | 属地网信办（线上系统 + 纸质） | **4~8 个月**（首报合格约 3 个月；有补正则 4~6 个月） |
| **大模型登记**（生成式 AI 服务登记） | **仅调用**第三方**已备案**大模型 API，**不做任何二次训练**，只做应用层封装 | **省级网信办单级审核** | 属地网信办（多数省份纸质 + 电子） | **15~45 个工作日**（约 3~4 个月含材料准备） |
| **算法备案** | 五类算法服务：**生成合成** / 个性化推送 / 排序精选 / 检索过滤 / 调度决策 | 省级初审 → 国家网信办复审 | `beian.cac.gov.cn` | 与登记并行 |

> 一句话区分：**算法备案管「算法机制透明」，大模型备案/登记管「模型内容安全」。**
> 自研团队常需「算法备案 + 大模型备案」；**只调 API 的团队 = 「算法备案 + 大模型登记」**。

### 1.1 判定「备案 vs 登记」的唯一硬标准

**有没有改动模型权重？有没有重新训练 / 深度微调？**

- **有** → 走**大模型备案**（重通道）。
- **没有**（只调 API 做应用封装、Prompt 优化、界面开发）→ 走**大模型登记**（轻通道）。

### 1.2 ⚠️ 容易踩的边界：二次处理可能被「升级」为备案

若在前端对 API 输出做了**内容过滤、重组、安全审核、格式优化等实质性二次加工**，
网信办**可能**认定构成对模型的「实质性修改」，从而要求**从「登记」升级为「备案」**（周期从 3~4 个月变 6~8 个月）。
反之，**仅调整 Prompt、前端参数、页面交互 = 应用层优化，仍走登记**。

> **对本项目的直接影响**：FishAgent 在模型输出后还要叠加「分档规则引擎 → 结构化结论」。
> 这一步是否被认定为「实质性二次加工」，**必须向属地网信办书面确认**（见 §10）。
> 为降低风险，建议把规则引擎定位为**「基于模型文本的确定性事实计算」**（气压/温差分档是查表计算，
> 不重写模型语义），并与模型输出在文档与实现上**解耦**。

## 2. 我方适用性判定

| 维度 | 我方情况 | 影响 |
|---|---|---|
| 服务形态 | 微信小程序，**面向境内公众**（含内测版） | 落入《暂行办法》第二条适用情形 |
| 输出内容 | AI 生成的**鱼情结论 + 钓位建议**（文本） | 属「生成合成内容」，触发**标识办法**义务 |
| 模型来源 | **调用第三方已备案大模型 API**（通义 / 豆包 / 文心等），不做权重微调 | → **登记**通道（非备案） |
| 算法类型 | 生成合成 + （若做个性化排序）排序精选 | → **算法备案**（生成合成类，或含排序精选类） |
| 舆论属性/社会动员能力 | 钓鱼决策建议，**风险属性较低**，但仍是面向公众的对话式生成 | **保守认定：需要备案/登记 + 算法备案** |

### 2.1 判定结论

> **FishAgent 需要办理：① 大模型登记（省级）+ ② 算法备案（生成合成类）。**
> **不需要**办「大模型备案」——前提是**全程不改动模型权重、不做预训练/微调**。
>
> **接入已备案大模型 ≠ 免责**：上游模型厂商的备案覆盖的是「原厂直接向用户提供服务」，
> 我方作为面向公众的**服务提供者**，仍须**独立完成登记**，不能拿上游备案号替代。

### 2.2 一个必须澄清的灰区

《暂行办法》第十七条的表述是「**提供具有舆论属性或者社会动员能力**的生成式 AI 服务的，应当……开展
**安全评估**，并……履行**算法备案**」。而「**登记**」义务来自**各地网信办对调用方应用的实施细则**
（国家网信办备案公告亦明确：通过 API 直接调用已备案模型能力的应用或功能，**必须由地方网信办开展登记**）。

- 「钓鱼工具」是否具备「舆论属性/社会动员能力」**存在解释空间**：一种观点认为纯工具类不构成舆论属性，
  可不做算法备案；另一种观点认为只要面向公众生成内容即需备案。
- **务实做法**：按**保守口径**（登记 + 算法备案）准备，并**向属地网信办确认「纯工具类」是否可简化**。
  宁可多办，不可漏办——2026 年监管明显收紧（见 §6）。

## 3. 「要不要办」的两个判断条件（官方口径）

1. **面向境内公众提供服务**——API、SaaS、小程序、APP、网页、公众号等**所有公开形态**均算；
   仅内部使用、非公开、无用户交互的服务不强制备案。
2. **具有舆论属性或社会动员能力**——以内容生成与分发为核心功能的 AI 产品通常落入该范畴。

> 各地网信办判断尺度不完全一致；**拿不准时先咨询属地网信办**。

> **对 FishAgent 的适用**：内测版一旦**对非特定用户开放**即算「面向公众」。
> 因此 **M2 内测上线前就应把登记材料准备好**，不能等 M3 Agent 化才启动。

## 4. 登记流程（我方主路径，标准五~六步）

| 阶段 | 内容 | 我方要点 | 参考时长 |
|---|---|---|---|
| 1. 业务自查与路径判定 | 确认产品形态、模型来源；核验上游模型**已在全国网信办公示备案名单**内 | 选定并留存上游模型的**备案编号 + 公示截图 + API 协议**；确认无权重微调 | 1~3 天 |
| 2. 材料筹备 | 三类材料（见 §5） | **最耗时** | **7~15 天**（预留 30 天更稳） |
| 3. 提交 | 向**工商注册地属地**网信部门提交（纸质盖章 + 电子版） | 用官方**《生成式人工智能服务登记申请表》模板**，勿自制 | 1~2 周 |
| 4. 初审与补正 | 形式审查 + 实质审查；可能下发补正通知 | 补正后**重新排队**，务必一次到位 | 随情况 |
| 5. 线上技术核验 | 监管用测试账号实测：**拦截/拒答能力、日志可追溯、AI 标识** | 提前准备 **3~5 个全功能测试账号** | — |
| 6. 通过 → 公示 → 上线 | 下发**登记编号**，产品显著位置展示 | 上线后**重大变更须办变更登记** | — |

## 5. 材料清单（登记，三类）

### （1）企业基础资质
- 营业执照（加盖公章）；法人身份证；联系人 / 安全负责人信息
- 域名证书、**ICP 备案**截图、**公安网安备案**凭证

### （2）模型调用合规材料
- 上游大模型**备案公示截图 + 官方备案编号**
- API 调用合作协议 / 官方授权文件
- **技术说明文档**：声明「仅调用 API、不存在模型训练/微调」（技术负责人签字 + 公章）
- 接口技术文档、**服务部署架构图**（证明**服务器在中国大陆境内**）

### （3）安全治理核心材料（审核重点）
- **内容安全管理制度**：技术拦截策略、人工审核机制、巡检规则、用户投诉处置流程
- **敏感风险词库**（覆盖政治、暴力、色情、谣言等多类，并提供持续更新机制）
- **用户隐私保护方案、隐私政策、用户服务协议**
- 风险应急预案、**AI 生成内容溯源标识方案**
- 测试账号（3~5 个全功能账号，供线上核验）

> **若被升级为「大模型备案」**，额外需：安全评估报告、**语料标注规则**、**拦截关键词列表**、
> **评估测试题集**（生成题库 ≥2000 条、风险拒答专项 ≥500 条、关键词库建议 ≥1 万词）、
> 以及依据 GB/T 45644《生成式人工智能服务安全基本要求》的量化测试数据。

## 6. 内容标识义务（《人工智能生成合成内容标识办法》，2025-09-01 施行）

| 义务 | 要求 | 我方落地 |
|---|---|---|
| **显式标识** | 生成内容须以文字/声音/图形等**用户可明显感知**的方式标注 | 鱼情结论页显著位置标注「**AI 生成 · 仅供参考**」（对应实现红线 **R6**，原型 `factors.render_explanation(note_ai=True)` 已预留） |
| **隐式标识** | 在文件元数据中写入生成合成属性、服务提供者名称/编码、内容编号 | 纯文本小程序场景需在输出结构/导出文件中携带；**待 M2 设计确认承载方式** |
| **用户协议** | 第八条：服务协议须**明确说明标识的方法、样式**并提示用户 | 写入《用户服务协议》 |
| **分发平台核验** | 第七条：**应用分发平台**（含小程序）上架审核时须核验标识材料 | 提审材料需附标识方案 |
| **日志留存** | 第九条：对**去除显式标识**的提供对象，留存日志**≥6 个月** | 一般不提供「无标识」内容；若提供则须留日志 |

> **重要**：标识办法第十二条要求——在履行**算法备案、安全评估**时**一并提交标识相关材料**。
> 即标识方案不是「上线前再补」，而是要**随备案/登记材料一起交**。

## 7. 主体资质红线：个人不能办

> **备案/登记主体必须是「在中国境内依法设立的独立法人企业」**；**自然人、个体工商户均无法提交备案**。

- KBB OPC（一人有限责任公司）**属独立法人企业**，**满足主体资格** ✅。
- ⚠️ 若最终以**个人开发者 / 个体工商户**身份运营，则**无法办理登记**——这是比技术更早暴露的红线。
- 前置资质顺序：**工商主体 → ICP 备案 → 公安网安备案 → 大模型登记 / 算法备案**。

## 8. 时间线与「合规前置」建议

| 节点 | 建议动作 |
|---|---|
| **M1（现在）** | ① 确认主体为独立法人企业；② 选定**已备案**上游大模型并留存其备案编号；③ **即启动**属地网信办咨询（拿到「工具类是否需要算法备案」的明确口径）；④ 编写技术说明/安全制度初稿 |
| **M2（内测前）** | ① 完成**登记**（内测对外即属「面向公众」）；② 落地**显式标识**；③ 隐私政策/用户协议就位；④ 准备测试账号 |
| **M3（Agent 上线前）** | ① 完成**算法备案**；② 补齐**隐式标识**；③ 产品内**公示登记/备案编号** + 投诉举报入口（对应 R6 与《暂行办法》第十五条） |
| **重大变更时** | 更换上游模型、新增多模态、功能大改 → 及时办**变更登记/备案** |

> **总工期敏感**：登记约 **3~4 个月**、备案约 **4~8 个月**。若产品排期紧，**M1 必须启动**，
> 否则「先上线后补票」在 2026 年监管下**代价极高**。备案为**「上线一批、备案一批」滚动受理**，**无申报截止日**。

## 9. 结论与建议

| 项 | 结论 |
|---|---|
| 路径判定 | **大模型登记（省级）+ 算法备案（生成合成类）**；**无需**自研大模型备案 |
| 风险等级 | 🟡 **中高**：路径清晰，但**工期较长（3~8 个月）**且**灰区（工具类是否需算法备案、二次处理是否升级）需书面确认** |
| 是否阻塞项目 | **不阻塞技术开发**，但**阻塞「合规上线」**——**M2 内测前必须完成登记** |
| 前置红线 | 主体须为**独立法人企业**（KBB OPC ✅）；**服务器必须境内** |
| **建议动作** | ① **M1 即联系属地网信办**确认口径；② 选定并锁定**已备案**大模型供应商；③ 先把**安全制度/隐私政策/用户协议/标识方案**四件套写好（登记核心材料）；④ 内测前完成登记 |
| 是否需专业机构 | 中小团队**建议委托**合规机构代办（首次申报易因材料口径被打回，补正即重排队） |

> **对 G1 的影响**：T10 由「🔴 未知工期」降级为「🟡 路径明确、工期可控（登记 3~4 个月）」，
> **不改变 G1 的 Go 结论**，但**必须写入 M2/M3 排期**并与**载体（T09）**、**数据授权（T11/T12）**并列跟踪。
