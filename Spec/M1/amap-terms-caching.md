# M1-T11 高德条款对 POI 缓存 / 持久化的限制（护城河合法性）

> 对应 Roadmap §2.2 M1-T11（🔴 「护城河」合法性的地基）、立项文档 7.7；TechStack D6。
> 结论：**🔴 高风险 —— 高德《开放平台服务协议》默认「禁止」对 POI 等结果进行存储 / 缓存 / 持久化，
> 且明确禁止「制作衍生品 / 二次包装」。基于高德数据沉淀 UGC 钓点库，属需「事先书面同意」的行为。**
> 依据：《高德地图开放平台服务协议》（更新日期 **2025-12-03**，官网 `developer.amap.com/pages/terms/`）
> 及《开发者合规指南》（更新日期 **2025-12-03**）。

---

## 1. 结论摘要（先给答案）

| 问题 | 结论 |
|---|---|
| POI 结果能否**缓存 / 持久化入库**？ | **默认不能。** 协议多处（§3.5、§4.12.3、§7.3）明令禁止「存储、缓存、下载、镜像、复制」服务数据 |
| 能否**基于高德数据构建衍生数据库**（= UGC 钓点沉淀）？ | **默认不能。** §7.3 明确禁止「二次包装、制作衍生品、汇编、编撰」；需**事先书面同意** |
| 能否**与用户 UGC 混合存储**？ | **需书面确认。** UGC 若复制了高德 POI 的名称/地址/坐标，即落入衍生品；需高德书面许可 |
| 商业使用是否需要额外许可？ | **需要。** §3.2：法人/非法人组织用于**商业目的**，须事先购买**「技术服务许可」** |
| 能否脱离本服务单独展示数据？ | **默认不能。** §4.12.4 禁止脱离本服务单独使用或展示相关内容 |
| 是否需**署名**？ | **需要。** §7.4 授予在应用中使用「高德地图」字样的许可，仅用于说明使用了本服务；§4.10.7 禁止删除/遮挡版权声明 |
| 协议终止后？ | §12.2：必须**从应用与服务器删除**所有通过本服务获得的内容与数据 |

> **一句话**：**当前设计（把高德 POI 召回结果沉淀为自有钓点库）= 直接踩在 §7.3「制作衍生品」与 §3.5「禁止存储」上。**
> **这是「护城河」的合法性前提，必须在 M2 落库前解决，否则做大了就是违约。**

## 2. 核心条款摘录（原文，2025-12-03 版）

> 以下为协议原文节选，「相关内容」的范围在 §2.2 中被明确定义为**包含 POI 数据、坐标经纬度、地点数据、
> 地址数据、商家列表、路线规划**等——即我们的召回结果全部属于「相关内容」。

### 2.1 禁止存储 / 缓存（§3.5）

> **§3.5**　您只可使用在平台网站相应官方文档中所列明和开放的本服务的功能来对相关服务数据的结果进行展示，
> 但是您**不得直接存储、缓存或技术手段抓取、使用本服务内部数据、图片等相关内容**。……
> 若您有**脱离本服务使用服务数据等相关内容的需求，可以提交工单进行咨询**，我们将评估是否可以开展合作。

### 2.2 禁止抓取 / 缓存 / 索引（§4.12.3）

> **§4.12.3**　您不得使用任何漫游器、网络蜘蛛、网络爬虫、抓取工具、网站搜索/检索应用程序或其他工具访问、
> 抓取、爬取、**预读取、存储、缓存**、截图、检索或索引本服务及相关内容的任何一部分……

### 2.3 禁止脱离本服务单独使用 / 展示（§4.12.4）

> **§4.12.4**　您**不能脱离本服务单独使用或展示相关内容**，或擅自修改本服务的名称、展示方式……

### 2.4 禁止获利性提供（§4.12.5）

> **§4.12.5**　您不得将本服务以**收费或其他获利的方式**进行提供，无论是否为直接经济或金钱收益。

### 2.5 ★ 禁止制作衍生品 / 二次包装（§7.3，**最关键**）

> **§7.3**　未经高德事先书面同意，您不得为任何目的超出我们提供的授权范围使用本服务及相关内容，
> 更不得对本服务及相关内容进行包括但不限于**爬取、存储、缓存、下载、镜像、复制、截图、修改、改编、汇编、
> 编撰、翻译、二次包装、制作衍生品**、传播、出版、发行、转让、转售、销售、许诺销售、出借、出租、
> 转授权、再许可、分许可等任何侵害高德……合法权利及相关权益的行为。

### 2.6 商业目的需购买「技术服务许可」（§3.2）

> **§3.2**　若您是法人或非法人组织，需要事先从高德购买**技术服务使用许可**：
> §3.2.1 如您自行使用本服务（包括但不限于**向第三方或公众用户收费**、参与第三方项目投标、
> 用于内部管理系统或后台管理系统、以及**任何其他直接或间接获取收益或利益的目的**……）——须购买技术服务许可。
> §3.2.2 如您为第三方开发系统……则您及第三方系统运营方**均需**事先购买技术服务许可。

### 2.7 署名与品牌（§7.4 / §4.10.7）

> **§7.4**　高德在此授予您一项……在您的应用中使用**「高德地图」字样标志**的许可，
> 并且该使用许可的**唯一目的是用以说明在您的应用中使用了本服务**。
>
> **§4.10.7**　（禁止）**删除或遮挡本服务中包含的任何版权声明、商标声明或其他所有权声明**。

### 2.8 协议终止须删除数据（§12.2）

> **§12.2**　……如果您要单方终止……您必须先将本服务从您的应用上移除，并**从您的应用、服务器或其他设备上
> 删除所有通过本服务获得的一切相关内容、服务数据以及高德标志**。

## 3. 「护城河」的三重约束

| 约束 | 条款 | 对我方含义 |
|---|---|---|
| **不许落库** | §3.5 / §4.12.3 / §7.3 | POI 召回结果**不能持久化**为自有数据表 |
| **不许衍生** | §7.3 | 基于高德数据构建**衍生数据库 / 二次包装 / 汇编**须**事先书面同意** |
| **不许获利性转提供** | §4.12.5 / §3.2 | 商业目的须购买**技术服务许可**；不得把高德能力直接「转卖」 |

> 三重约束叠加，意味着**默认形态下「UGC 钓点沉淀 + 高德 POI 召回」不能合流入库**。

## 4. 判定：UGC 钓点沉淀的合法性

立项文档 7.7 的担忧得到证实——**「基于高德数据构建衍生数据库」正是 §7.3 点名禁止的行为**。

| 做法 | 风险 | 依据 |
|---|---|---|
| 把高德返回的 POI（名称/地址/坐标/POI ID）写入自有库 | 🔴 违约（存储 + 衍生） | §3.5、§7.3 |
| 用高德结果「喂」给用户 UGC 库、二者混存 | 🔴 违约（汇编 / 衍生品） | §7.3 |
| 运行时实时召回、**用完即弃（不落库）** | 🟢 合规（协议本意允许「展示」） | §3.5 首句 |
| 自有 UGC 数据**独立于高德**（不复制高德字段）存「用户上报坐标 + 用户自述」 | 🟡 需设计隔离，见 §5 | §7.3 边界 |
| 经**高德书面同意**后落库 / 合作 | 🟢 合规（走商务合作） | §3.5、§7.3 |

> **关键判断**：UGC 数据只要**来源是用户**（用户在地图上选点/上报），且**不复制高德的名称、地址、POI ID
> 等受保护字段**，则可主张为**独立数据**；但一旦「用高德召回结果反查、补全、合并」UGC，即越界。
> **这条边界必须由法务固定并在实现上强制隔离。**

## 5. 产品级对策（分档，供 M2 选型）

| 方案 | 说明 | 合规性 | 代价 |
|---|---|---|---|
| **A. 实时召回，不落库（推荐基线）** | POI/车程结果**仅内存使用**，计算完即弃；数据库只存用户 UGC 与缓存键的**哈希** | 🟢 最稳 | 无法做「离线钓点库」，每次依赖实时调用（成本 ↑） |
| **B. 双源解耦** | 引入**第二 POI 数据源**（其他开放地图/公开 POI 数据集）承载「钓点库」；高德仅用于**实时展示与导航跳转** | 🟢 | 需评估第二源授权；两源坐标体系要统一 |
| **C. UGC 独立建库** | 钓点库**只存用户上报坐标 + 用户内容**，**不含**任何高德字段；高德数据不参与入库 | 🟡 需严格实现隔离 | 冷启动更慢；需用户协议约定 UGC 授权 |
| **D. 与高德签商务合作** | 走 §3.5 工单 / §3.2 技术服务许可，争取**书面落库授权** | 🟢（获授权后） | 商务成本、周期不确定 |

> **建议**：M2 先按 **A（不落库）** 上线，同时并行推进 **D（争授权）**；若 D 可行再叠加 C 的 UGC 库。
> **禁止**在未获授权前实现「高德结果入库」。
