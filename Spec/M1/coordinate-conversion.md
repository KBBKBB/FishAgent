# M1-T05 坐标系转换验证

> 对应红线 **R1**（TechStack §5）与立项文档 4.2。
> 状态：`[x]` 本地算法已完整验证；高德官方转换 API 交叉校验待真实 Key。

## 1. 问题

- 手机 GPS / Open-Meteo → **WGS84**
- 高德所有 Web 服务 API → **GCJ-02**（火星坐标），仅接受 GCJ-02
- 境内偏差 50~500m，若混用会导致「推荐钓位落到对岸」

## 2. 方案

采用**纯算法本地转换**（`prototype/fishagent_m1/coord.py`）：

- `wgs84_to_gcj02(lat, lng)` / `gcj02_to_wgs84(lat, lng)` 作为**唯一转换入口**（R1）
- 反向转换用迭代法逼近，收敛阈值 1e-11 度
- 境外（`out_of_china`）不偏移
- **不消耗高德配额**：对应调用量预算中「坐标转换 → 客户端本地转换 → 降为 0」

> 备选：高德 `v3/assistant/coordinate/convert`。原型保留 `AmapClient.convert_amap()`
> 仅用于**交叉校验**，不作为主链路（避免配额消耗与网络依赖）。

## 3. 实测结果（本地算法，可复现）

| 城市 | WGS84 (lat,lng) | GCJ-02 (lat,lng) | 偏移 |
|---|---|---|---|
| 成都 | 30.657000, 104.066000 | 30.654578, 104.068508 | **361 m** |
| 北京 | 39.908700, 116.397500 | 39.910103, 116.403744 | **555 m** |
| 上海 | 31.230400, 121.473700 | 31.228458, 121.478223 | **481 m** |
| 广州 | 23.129100, 113.264400 | 23.126423, 113.269730 | **621 m** |

- **往返误差**：`wgs→gcj→wgs` 四点均 < **0.001 mm**（数值上等价于无损可逆）
- **偏移量**与文档「50~500m」同量级（北京/广州略超 500m，属该算法已知特性）
- 单测：`prototype/tests/test_coord.py`（4 项，含境外不变、偏移区间、往返精度）
