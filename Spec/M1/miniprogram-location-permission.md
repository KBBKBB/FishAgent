# M1-T09 小程序定位权限可行性确认（A7）

> 对应假设 **A7**、Roadmap §2.2 M1-T09（🔴 极高风险）、立项文档 4.4。
> 结论：**🔴 高风险 —— 钓鱼工具类目很可能不满足 `wx.getLocation` 的准入要求。必须准备降级方案。**
> 依据：微信官方《小程序地理位置接口申请与使用指引》《applyPrivacyInterface》接口文档（2026 现行）。

---

## 1. 规则摘要（官方，现行）

| 项 | 规则 |
|---|---|
| 准入起始 | **2022-04-18** 起，地理位置相关接口实行**准入开通**，非默认可用 |
| 申请方式 | 服务端调用 `applyPrivacyInterface`（`api_name` 严格区分大小写） |
| 代码声明 | 必须在 `app.json` 的 **`requiredPrivateInfos`** 中声明，否则**无法提交代码审核** |
| 隐私协议 | 必须配置**《用户隐私保护指引》**并声明「地理位置」；提审时校验一致性 |
| **类目要求** | **每个接口都有类目要求**，申请前必须读 API 原文；不符则报 **61036「该帐号不可申请，请检查类目是否符合」** |
| 辅助材料 | **必须提供** `url_list` / `pic_list` / `video_list` **三选一**（与真实使用场景相关）；不提供或重复机械提交将**无法提交** |
| 申请理由 | `content` ≤ 300 字符，UTF-8 编码 |
| 审核结果 | 推送至「开发资料-消息与事件 URL」；`status` 2=不通过 / 3=通过；`reason` 为驳回原因（如「小程序内未含有相应使用场景」） |

---

## 2. 关键风险：服务类目匹配度

`wx.getLocation` **仅对特定服务类目开放**。据公开汇总（2025-03，需以官方 API 文档为准），支持类目集中于：

| 支持的类目 | 场景 |
|---|---|
| 交通服务（代驾 / 租车网点 / 附近车辆 / 共享交通） | 出行 |
| 餐饮（点餐 / 外卖 / 服务场所） | 实际送餐 |
| **工具-信息查询 / 办公 / 设备管理** | ⚠️ 仅限「与地理位置相关的**打卡服务**（智能门禁、智能穿戴设备等）」 |
| 汽车服务（维修保养 / 4S / 二手车等） | 导航到店 |
| 电商平台 / 商家自营 | 线下发货收货 / 商超导览 |
| 金融（银行 / 非银） | 网点预约导航 |

### 2.1 我方匹配度评估

FishAgent 的场景是「**基于用户位置推荐附近钓位**」，拟设类目可能是「工具-信息查询」或「生活服务」。

- ⚠️ **「工具-信息查询」明确限缩为「打卡服务」场景**，**与「附近钓位推荐」不符**；
- 其余支持类目（交通/餐饮/汽车/电商/金融）均**与钓鱼工具无关**。

**判定：`wx.getLocation` 申请**很可能**因类目/场景不符被拒（61036 或「小程序内未含有相应使用场景」）。**

> ⚠️ 这是**第三方汇总**，最终必须以 `wx.getLocation` API 文档的**类目要求原文**为准——
> 但无论原文如何，「钓鱼工具 + 附近水域推荐」都不在已列举的支持场景内，**风险为高**。

## 3. 备选方案（M1 必须选定，避免被阻塞）

| 方案 | 定位能力 | 微信类目限制 | 体验损失 | 建议 |
|---|---|---|---|---|
| **A. 小程序 + 地图选点（推荐降级）** | 用户**手动拖动地图 marker 选点**，或**选择城市/区县** | ✅ **完全绕开隐私接口**（`<map>` 组件 + marker 不需要 getLocation） | 失去「自动定位」，多一步手动操作 | ✅ **首选降级** |
| B. 小程序 + `wx.getLocation` | 自动定位 | ❌ 受类目准入 | 无 | 先申请；被拒即转 A |
| C. H5 | 浏览器 Geolocation | ✅ 无微信类目限制 | 失去微信生态、需另建入口 | 备选 |
| D. 原生 App | 系统定位权限 | ✅ 无微信类目限制 | 开发/分发成本最高 | 最后手段 |

> **重要**：方案 A 让产品**不依赖定位权限即可上线**，A7 从「可阻塞项目」降为「体验优化项」。
> 建议 **M2 直接以方案 A 为默认交互**，`wx.getLocation` 作为增强（申请通过则自动定位，未通过则手动选点）。

## 4. 申请材料清单（若仍要申请）

| 材料 | 内容要点 |
|---|---|
| `api_name` | `getLocation`（注意大小写；另需 `chooseLocation` 若使用） |
| `content`（≤300 字） | 说明「用户主动发起，用于计算附近钓位可达性；位置用完即弃，不长期存储」 |
| **辅助材料（三选一，必须）** | **演示视频（mp4）** 最有效：录制「用户点击→授权→展示附近钓位」完整流程；或界面截图组 |
| 类目 | 先确认 `wx.getLocation` API 文档允许的类目，并在「账号设置-服务类目」中已添加对应类目 |
| 隐私指引 | 「账号设置-服务内容声明-用户隐私保护指引」中声明**地理位置**类型 |

### 4.1 常见驳回原因与应对

| 驳回/错误 | 原因 | 应对 |
|---|---|---|
| **61036** | 类目不符合 | 更换/新增允许的类目；否则放弃申请 |
| 「小程序内未含有相应使用场景」 | 线上版本无对应功能 | **先上线含该场景的版本**再申请；提供视频佐证 |
| 无法提交 | 未提供辅助材料 / 重复机械提交 | 提供真实场景视频；勿重复提交 |
| **61040** | 代码用了接口但未在 `requiredPrivateInfos` 声明，或未获权限 | 声明 `requiredPrivateInfos` + 先过权限审核 |
| 61039 | 检测任务未结束即提交审核 | 用 `getCodePrivacyInfo` 确认检测完成 |

## 5. 结论与建议

| 项 | 结论 |
|---|---|
| A7 判定 | 🔴 **高风险，倾向不可获批**（类目/场景不符） |
| 是否阻塞项目 | **若采用方案 A（地图选点）则不阻塞**；若坚持自动定位则可能阻塞 |
| **建议动作** | ① **M2 默认采用「地图选点 + 行政区选择」**（不依赖权限）；② 并行提交 `wx.getLocation` 申请作为增强；③ 申请前先确认类目要求原文；④ 若被拒，直接走方案 A，**无需改 H5/App** |
| 时点 | 立即启动（申请有审核周期，且需先有线上场景版本） |

> **对 G1 的影响**：A7 由「🔴 可阻塞」降级为「🟡 有明确降级路径」。
> 前提是 **M2 产品设计接受「手动选点」作为默认定位方式**——需产品侧确认。
