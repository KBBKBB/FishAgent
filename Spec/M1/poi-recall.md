# M1-T01 水域 POI 双路召回实测 / M1-T07 城区水域存量

> 对应假设 **A1**（召回率 ≥70%）、**A2**（一线 ≥5 / 三四线 ≥3）与立项文档 4.2。
> 状态：`[~]` 已用真实 AMAP_KEY 复测（2026-10-11）；**发现并修复「type 码路」缺失 Bug**（详见 §3.2）。

## 1. 为什么要双路召回

高德 POI 分类中水域相关类型覆盖度有限，**「水库」「野塘」等往往无法通过 type 码精确命中**。
故 MVP 采用 **「type/周边搜索 ∪ 关键词搜索（水库|湖|河|塘|野钓）」双路并集**。

原型实现：`prototype/fishagent_m1/poi.py`
- `recall_by_type()`：**type 码搜索**（`types=190200` 自然地名；2026-10-11 补，见 §3.2）
- `recall_around()`：周边搜索（可跨分片调用）
- `recall_text()`：关键词搜索
- `recall_dual()` / `dedup_by_id()`：并集 + 按 id 去重

## 2. A1 召回率测试方法（Roadmap §2.1 M1-T01）

| 项 | 口径 |
|---|---|
| 城市 | 3 个试点城市（一线/二线/三四线各 1） |
| 真值集 | 每城 **50 个已知钓点**（人工核验存在且可钓） |
| 命中判定 | 召回 POI 名称包含真值名（或反之） |
| 通过标准 | **召回率 ≥ 70%** |
| 代码 | `poi.measure_recall(ground_truth_names, recalled)` → `RecallResult.recall_rate` |

> ⚠️ 真值集必须**先于召回结果**独立建立，避免「用召回结果倒推真值」的循环论证。

### 3.2 ★ 关键发现：原实现漏掉了立项文档 4.2 的「type 码」路

立项文档 4.2 规定的双路召回是 **「type 码 + 关键词」**。但原型早期实现把「type 码路」写成了
**「带关键词的周边搜索」**（`recall_around(keywords=...)`），与关键词路**同源**，
导致**两条路用同一套关键词过滤**——凡命名不含 `水库|湖|河|塘|野钓` 的水体被**系统性漏召回**。

**实测证据（2026-10-11）**：

| 实验 | 结果 |
|---|---|
| 关键词路（`keywords=水库\|湖\|河\|塘\|野钓`）周边搜索 | 命中 `苏州河`，**漏掉 `黄浦江`** |
| type 码路（`types=190200` 自然地名）周边搜索 | 命中 **`黄浦江`、`吴淞江(苏州河)`、`彭越浦`、`日晖港`、`白莲泾`、`沙泾港`** 等 |
| 纯关键词 `江` 文本搜索 | **噪声**（返回餐馆/小区，无水体）→ 关键词路无法靠加 token 修复 |

**高德水域 POI 类型码（实测）**：

| typecode | 含义 | 示例 |
|---|---|---|
| `190200` | 地名地址信息;自然地名（大类） | 黄浦江、苏州河 |
| `190204` | …自然地名;**河流** | 黄浦江、吴淞江、彭越浦、白莲泾 |
| `190205` | …自然地名;**湖泊**（含水库） | 淀山湖、紫坪铺水库 |
| `110200/110203` | 风景名胜类（部分湖泊归类于此） | 三岔湖景区、汉源湖湿地公园 |

**修复**：已在 `prototype/fishagent_m1/poi.py` 补齐 `recall_by_type()`（`types=190200`），
接入 `recall_dual()` 与实测工具 A1/A2（`config.WATER_TYPECODES`），新增单测 `tests/test_poi_type_recall.py`。
**效果**：三城召回率 **+8~10 个百分点**，召回 POI 总量提升 **约 3~4 倍**（993→2911 / 792→3145 / 719→3091）。

### 3.3 未命中项归因（补齐 type 码路后仍缺失的）

| 城市 | 仍未命中 | 类型 |
|---|---|---|
| 上海 | 共青森林公园（**公园，非水域 → 真值集瑕疵**）、夏阳湖、大莲湖（小湖，翻页深度）、淀浦河、蕰藻浜（**浜类命名**） | 小水体 + 命名 |
| 成都 | 白塔湖、龙泉湖（小湖，翻页深度） | 小水体 |
| 雅安 | 天全河、宝兴河（**偏远 >150km**）、瀑布沟水库、飞仙关水库（**偏远**） | 偏远 |

**结论**：补齐 type 码路后，缺口进一步收敛为 **① 小水体的翻页深度**、**② 偏远水域的覆盖半径**、
**③ 少量特殊命名（浜）**。大型湖库与主流河道（黄浦江、青衣江、沱江、苏州河）已可稳定召回。

> ⚠️ **真值集状态：draft-unverified（未人工核验）**。names 来自公开资料、独立于召回结果建立，
> 但**存在性与「可合法垂钓」未经人工核验**（如「共青森林公园」实为公园）。因此上表**不能作为 A1 的最终判定**，
> 仅表明 **A1 存在实质风险**，须经人工核验真值集后复测。

### 3.4 待补：正式判定条件

1. 人工核验三城真值集（剔除公园等非水域，确认「可合法垂钓」）；
2. 每城扩至 50 点；
3. 复测后据 A1 结果触发 G1 判定（若 <50% → Plan B1）。

## 4. A2 / M1-T07 城区有效水域存量测试

| 项 | 口径 |
|---|---|
| 有效水域 | 经人工核验**可合法垂钓**且**往返车程 ≤2h** |
| 测试点 | 3 城（一线/二线/三四线各 1）**各取 5 个随机城区坐标点**，分别评估后**取中位数** |

| 依赖 | 车程精算（`route.py`）已就绪 |

> 原版「城区 ≥5 个」未定义城市分档，一线与县城不可比，故本口径改为三档 + 中位数。

### 4.1 实测结果（2026-10-10 / 2026-10-12）

参数：`coverage_km=80, spacing_factor=1.414, max_pages=1, max_candidates=40`

| 城市 | 档位 | 5 点计数 | 中位数 | 阈值 | 达标 |
|---|---|---|---|---|---|
| 上海 | 一线 | [40, 40, 40, 40, 40] | **40** | 5 | ✅ |
| 成都 | 二线 | [40, 40, 40, 40, 40] | **40** | 4 | ✅ |
| 雅安 | 三四线 | [38, 40, 37, 37, 37] | **37** | 3 | ✅ |

**2026-10-12 复测（补齐 type 码路后；参数同上）**：

| 城市 | 档位 | 5 点计数 | 中位数 | 阈值 | 达标 |
|---|---|---|---|---|---|
| 上海 | 一线 | [40, 40, 40, 40, 40] | **40** | 5 | ✅ |
| 成都 | 二线 | [40, 40, 40, 40, 40] | **40** | 4 | ✅ |
| 雅安 | 三四线 | [40, 39, 40, 37, 40] | **40** | 3 | ✅ |

> 数据：`measurements/a2-2026-10-12.json`。雅安中位数由 37 升至 40（type 码路增补召回）。

> ⚠️ **口径说明（诚实披露）**：`max_candidates=40` 使一线/二线中位数**恰等于上限 40 → 被截断**，
> 真实值 **≥40**。三四线（雅安）中位数 37 < 40，为**未截断的真实值**。
> 结论「全部达标」成立（阈值 5/4/3 远低于测得值），但如需精确上限，应提高 `max_candidates` 复测。
> 数据：`measurements/a2-2026-10-10.json`。
