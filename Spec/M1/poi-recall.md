## 1. 为什么要双路召回

高德 POI 分类中水域相关类型覆盖度有限，**「水库」「野塘」等往往无法通过 type 码精确命中**。
故 MVP 采用 **「type/周边搜索 ∪ 关键词搜索（水库|湖|河|塘|野钓）」双路并集**。

原型实现：`prototype/fishagent_m1/poi.py`
- `recall_around()`：周边搜索（可跨分片调用）
- `recall_text()`：关键词搜索
- `recall_dual()` / `dedup_by_id()`：并集 + 按 id 去重

## 2. A1 召回率测试方法（Roadmap §2.1 M1-T01）

| 项 | 口径 |
|---|---|
| 城市 | 3 个试点城市（一线/二线/三四线各 1） |
| 真值集 | 每城 **50 个已知钓点**（人工核验存在且可钓） |
| 命中判定 | 召回 POI 名称包含真值名（或反之） |
| 通过标准 | **召回率 ≥ 70%** |
| 代码 | `poi.measure_recall(ground_truth_names, recalled)` → `RecallResult.recall_rate` |

> ⚠️ 真值集必须**先于召回结果**独立建立，避免「用召回结果倒推真值」的循环论证。

## 4. A2 / M1-T07 城区有效水域存量测试

| 项 | 口径 |
|---|---|
| 有效水域 | 经人工核验**可合法垂钓**且**往返车程 ≤2h** |
| 测试点 | 3 城（一线/二线/三四线各 1）**各取 5 个随机城区坐标点**，分别评估后**取中位数** |
| 通过标准 | **一线 ≥5 个，三四线 ≥3 个** |
| 依赖 | 车程精算（`route.py`）已就绪 |

> 原版「城区 ≥5 个」未定义城市分档，一线与县城不可比，故本口径改为三档 + 中位数。

### 4.1 实测结果（2026-10-10）

参数：`coverage_km=80, spacing_factor=1.414, max_pages=1, max_candidates=40`

| 城市 | 档位 | 5 点计数 | 中位数 | 阈值 | 达标 |
|---|---|---|---|---|---|
| 上海 | 一线 | [40, 40, 40, 40, 40] | **40** | 5 | ✅ |
| 成都 | 二线 | [40, 40, 40, 40, 40] | **40** | 4 | ✅ |
| 雅安 | 三四线 | [38, 40, 37, 37, 37] | **37** | 3 | ✅ |

> ⚠️ **口径说明（诚实披露）**：`max_candidates=40` 使一线/二线中位数**恰等于上限 40 → 被截断**，
> 真实值 **≥40**。三四线（雅安）中位数 37 < 40，为**未截断的真实值**。
> 结论「全部达标」成立（阈值 5/4/3 远低于测得值），但如需精确上限，应提高 `max_candidates` 复测。
> 数据：`measurements/a2-2026-10-10.json`。
