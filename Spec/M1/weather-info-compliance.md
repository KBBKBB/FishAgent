# M1-T13 气象信息传播合规确认

> 对应 Roadmap §2.2 M1-T13（🟡 中）、立项文档 7.5。
> 结论：**🟡 中风险 —— 我们不构成「气象预报发布」，但构成「气象信息服务」，须完成「气象信息服务单位备案」；
> 且原型当前输出的具体气象要素数值（气压 hPa / 云量 %）属合规灰区，须按 R8 收敛为「结论 + 因子解释」。**
> 依据：《气象预报发布与传播管理办法》（中国气象局令第 26 号，2015-05-01 施行）、《气象信息服务管理办法》
> （中国气象局令第 27 号，2015-06-01 施行，2020 修订）。

## 1. 结论摘要（先给答案）

| 问题 | 结论 |
|---|---|
| 是否需要**气象信息服务资质**？ | **不需要特殊资质**，但**须备案**：作为「气象信息服务单位」，向**营业执照注册地省级气象主管机构备案**（令 27 号 §7） |
| 能否**向社会发布气象预报**？ | **绝对不能。** 气象预报实行**统一发布制度**，**其他任何组织或个人不得以任何形式向社会发布气象预报**（令 26 号 §6；令 27 号 §16(一)） |
| 我们的「鱼情结论」算不算「发布预报」？ | **不算**——它是**基于气象资料的二次加工信息服务结论**，不是气象台预报的发布 |
| 能否**展示原始气象数值**（气压/温度/降水）？ | **灰区**。若被视为「传播气象预报」，**须使用气象台最新预报并注明气象台名称与发布时间、不得更改**（§9），否则罚（§14(三)(四)）。**建议不展示原始预报数值** |
| 数据源合法性？ | **须能证明「合法渠道」**（令 27 号 §9(一)、§18(一)）；Open-Meteo 的上游许可需穿透确认（与 **T12** 联动） |
| 罚则？ | 非法发布 / 不使用最新预报 → 警告 + **≤5 万**（§12）；不注明来源 / 擅自更改 → 警告 + **≤3 万**（§14）；气象信息服务违规 → **≤3 万**（§18） |

> **一句话**：**合规姿态 = 「气象信息服务单位」（备案 + 合法数据源 + 只输出结论），而不是「气象预报传播者」。**

## 2. ★ 一个重要更正：立项文档引用的是**已废止**的旧办法

立项文档 7.5 引用的是《**气象预报发布与刊播管理办法**》（中国气象局令第 6 号，2003）。该办法
**已于 2015-05-01 废止**，现行有效的是《**气象预报发布与传播管理办法**》（令第 26 号）。
两者的核心义务相近，但**「刊播」→「传播」、条款编号与罚则均已变化**。建议同步修订立项文档 7.5 的法规名称。

## 3. 关键条款摘录（现行原文）

### 3.1 统一发布制度（令 26 号）

> **§6**　气象预报实行**统一发布制度**。各级气象主管机构所属的气象台应当按照职责……向社会发布……
> **其他任何组织或个人不得以任何形式向社会发布气象预报。**

> **§9**　鼓励媒体和单位传播气象预报。媒体和单位传播气象预报应当**使用当地气象主管机构所属的气象台提供的
> 最新气象预报**，并**注明气象预报发布的气象台名称和发布时间**，**不得自行更改气象预报的内容和结论**。

> **§3**　「公众气象预报」定义为……气温、湿度、**气压**、降水、风向、风速……等**气象要素预报**。
> ⟹ **气压/降水/风等属「气象预报」范畴**——这正对应我方因子引擎所用的数据。

> **罚则**：§12（非法发布 / 不用最新预报 → ≤5 万）；§14（**不注明发布单位与时间** / **擅自更改内容结论** → ≤3 万）。

### 3.2 气象信息服务单位备案（令 27 号）

> **§3**　「气象信息服务」是指**气象信息服务单位利用气象资料和气象预报产品，开展面向用户需求的信息服务活动**；
> 「气象信息服务单位」是指**依法设立并从事气象信息服务的法人和其他组织**。

> **§7**　气象信息服务单位应当**向其营业执照注册地的省、自治区、直辖市气象主管机构备案**……（领取营业执照后 **3 个月**内办理）。

> **§9**　从事气象信息服务的单位应当：（一）**使用合法渠道获得的气象资料和气象预报产品**；（二）建立业务规范和管理制度；（三）遵守气象技术标准。

> **§16**　**禁止**气象信息服务单位从事下列活动：（一）**向社会发布公众气象预报、灾害性天气警报和气象灾害预警信号**；……

> **§18**　（使用非气象台资料且**不能证明合法渠道** / **逾期未备案** → 责令改正，拒不改正**警告 + ≤3 万**）。

## 4. 我方定位判定

| 维度 | 我方情况 | 判定 |
|---|---|---|
| 是否「发布气象预报」？ | 我们不发布气象台的预报原文，输出的是**鱼情结论** | ✅ **不构成「发布」**（不触 §6/§16(一)） |
| 是否「气象信息服务」？ | 利用气象资料**开展面向用户需求的信息服务**（鱼情分析） | ⚠️ **构成** → 须按令 27 号 **备案** |
| 是否「传播气象预报」？ | 取决于是否展示气象要素数值（见 §5） | ⚠️ **灰区**，需按 §9 处理或规避 |
| 数据源合法性？ | Open-Meteo（上游含各国气象机构） | ⚠️ 须能证明「合法渠道」→ 与 **T12 授权清单**联动 |

> **判定**：FishAgent 应自我定位为**「气象信息服务单位」**，履行**备案 + 合法数据源 + 只出结论**三项义务。

## 5. ★ 灰区：原型输出已含具体气象要素数值

`prototype/` 的鱼情输出（`demo.py --mock`）当前形如：

```
1. 气压绝对值(当地归一化)：气压 1015.6hPa，位于当地 30~70 百分位 ……  [+20/20]
2. 云量/光照：多云（云量 59%）  [+5/5]
```

- 「**气压 1015.6hPa**」「**云量 59%**」属令 26 号 §3 定义的**气象要素**。
- 若被认定为「**传播气象预报**」，则按 §9 必须**使用气象台最新预报 + 注明气象台名称与发布时间 + 不得更改**；
  我们数据来自 Open-Meteo 而非气象台，**无法满足 §9**，且可能触 §14(三)（不注明来源）。
- **但这并非致命**：只要定位为「**二次加工的信息服务**」且**不呈现为「天气预报」**，
  即落在令 27 号允许的「面向用户需求的信息服务」范畴——**前提是数据源合法 + 完成备案**。

> **结论**：**「展示原始数值」不是必须，但「风险点」明确**——应把输出从「数值播报」改为「**结论 + 因子解释**」。

## 6. 产品级对策（对应实现红线 R8）

| 对策 | 说明 | 落地 |
|---|---|---|
| **R8 只出结论，不播报预报** | 输出「鱼口活跃度 + 原因」而非「气压 X hPa、明日天气」 | 已在 `factors.render_explanation()` 体现（含「非气象预报」声明） |
| **收敛原始数值** | 因子解释改用**相对分档/百分位**（如「气压位于最佳区间」）而非绝对数值，或对数值标注来源与时间 | **M2 需调整**（当前原型仍打印 hPa/%） |
| **避免「预报」语义** | 不使用「明日/未来天气」「天气预报」等表述；不提供天气播报式页面 | 设计约束 |
| **标注来源** | 若确需展示气象数据，标注数据来源与发布时间、不做「预报」呈现 | M2 设计 |
| **数据源合法可证** | 保留 Open-Meteo 及上游的**合法渠道证明/许可链** | 与 **T12** 联动 |

> 注：立项文档 7.5 已提出「只输出鱼情结论与因子解释」，本文件将其**从「建议」升级为「须落地的合规动作」**。
