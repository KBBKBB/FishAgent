## 二、M1 调研深化

**目标**：**不写业务代码，只验证假设。** M1 的产出是"能不能做"的答案，不是功能。

### 2.1 技术验证任务

| 编号 | 任务 | 验证内容 | 通过标准 | 对应假设 |
|---|---|---|---|---|
| **M1-T01** | 水域 POI 双路召回实测 | type 码 + 关键词（水库\|湖\|河\|塘\|野钓）双路召回的召回率 | **≥ 70%**（3 个试点城市各取 50 个已知钓点） | **A1** |
| **M1-T02** | 周边搜索半径分片方案实测 | 同心环/网格多圆心 vs 多边形搜索分片，两者调用量与召回效果对比 | 选出可行方案，明确单次半径 ≤ 50km 约束下的覆盖策略 | — |
| **M1-T03** | `entr_location` 端点可用性验证 | `extensions=all` 是否稳定返回入口坐标，缺失率多少 | 缺失率可接受，回退策略明确 | — |
| **M1-T04** | 距离测量接口开放性 + 实时路况确认 | ① `v3/distance` 是否对新 Key 开放 ② 是否返回 `duration` ③ `type=1` 是否计入实时路况 | 三项全通过，或 v5 替代方案可行 | **A4** |
| **M1-T05** | 坐标系转换验证 | `v3/assistant/coordinate/convert` 转换精度；WGS84→GCJ-02 回归校验 | 已知点校验误差在可接受范围 | — |

## 七、关键假设与 Go / No-Go 决策门

### 7.1 关键假设清单

| 编号 | 假设 | 验证方式 | 判定标准 | 时点 |
|---|---|---|---|---|
| **A1** | 水域 POI 双路召回可达可用水平 | 3 城市各取 50 个已知钓点测召回率 | **召回率 ≥ 70%** | M1 |
| **A2** | 城区 2h 车程内存在足量有效水域 | 三档城市实测 | **一线 ≥ 5，三四线 ≥ 3** | M1 |
| **A3** | 免费配额可支撑内测 | 按调用量表实测各接口独立配额 | **个人 Key 日配额 ≥ 3 万次** | M1 |

| **A6** | 用户愿意为"决策"打开 App | 内测期日活/留存观察 | 次日留存 ≥ 25%，含"未出钓也查看"占比 ≥ 20% | M2 |

| **A8** | 单次对话成本可接受 | 实测 token 消耗 × 单价 | **≤ ¥0.05 / 次对话** | M2 |

### 7.2 决策门（Go / No-Go）

| 门 | 时点 | Go 条件 | No-Go 触发后的动作 |
|---|---|---|---|
| **G1** | M1 末 | A1 + A2 + A3 + A4 全部通过 | 若 **A1 < 50%** 或 **A2 一线 < 3 个**：启动 **Plan B1**；若接口能力不成立（A4 失败）且无替代方案：**终止立项** |
| **G2** | M2 末 | A5 ≥ 70% 且 A6 次日留存 ≥ 25% | 若 A5 < 60% 或留存 < 15%：**停止规则引擎投入**，转向纯工具化（只做车程可达 + 钓点库）或终止 |
| **G3** | M3 末 | 有可验证的付费意愿信号 | 若无：转 To B（渔具店 / 黑坑导流）或暂停社区化投入 |

## 八、Plan B：主线失败时的转向预案

| 预案 | 触发条件 | 转向内容 |
|---|---|---|
| **B1** | POI 召回不足（A1 < 50%） | 放弃"全量水域召回"，转为 **UGC 钓点众包 + 车程排序**——用户主动上报钓点，产品负责可达性计算与排序。此时 UGC 从"护城河"升为"唯一数据源"，**M4 必须提前** |
| **B2** | 鱼情预测不准（A5 < 60%） | 放弃"预测鱼口"，转为 **记录 + 统计**——只呈现历史同时段出鱼数据，不做结论。**诚实的产品形态优于不准的预测** |
| **B3** | 用户需求不成立（A6 不达标） | 转 **To B**，把车程可达性 + 水域数据能力卖给渔具店、黑坑、垂钓园 |

## 九、验收指标（MVP 内测期）

### 9.1 口径总则

1. **统计周期**：默认**内测期连续 14 天**；未满 14 天不作达标判定。
2. **样本量下限**：单一指标样本 **< 30 条不下结论**（只记录）；标注 ★ 的关键指标**样本 N ≥ 100**。
3. **用户口径**：活跃用户 = 当日有 ≥ 1 次有效交互（提问或查看推荐）的用户。
4. **P95 定义**：服务端自收到请求到返回完整响应体的耗时，**不含客户端渲染与公网传输**；采样**同时包含成功与失败**请求。
5. **披露要求**：每条指标复盘必须同时输出 **分子 / 分母 / 样本量 / 观察窗口 / 测量人**，缺任一项视为未测量。
6. **三级分开**：**门禁（K）** 不达标不得上线；**目标（T）** 未达成需给出偏差归因；**观察（O）** 只记录不考核。

### 9.3 关键口径明细（不写清就无法测量）

- **K01 高危禁钓区漏出率 ★**
  - 分子：抽查到的推荐结果中，落入**饮用水水源一级保护区、禁渔期天然水域**的条数；分母：抽查总条数。
  - 抽样：人工抽检 **N ≥ 100 条推荐结果**，覆盖 3 个试点城市。
  - **可达成性前提**：高危类型**不得依赖人工维护名单**，必须接入权威矢量边界数据，或保守排除。
- **K02 一般禁钓区漏出率 ★**：分子为落入**承包塘/养殖区/危险区域**的条数，分母同上。此类依赖用户举报与运营维护，名单必然不全，故设 ≤ 1% 而非 0。
- **K03 隐私**：代码审计 + 生产库抽检，确认无精确位置明文长期存储；发现即阻断上线。
- **K04 埋点**：T01/T02/T09/T10 依赖的埋点必须 100% 覆盖，**否则这些指标的数字不可信**，故设为门禁。
- **T01 出钓用户预测认可率 ★**
  - 分子：**抽样回访**中认为预测与实际相符的**出钓**用户数；分母：有效回访的**出钓**用户数。
  - **禁止使用"用户主动标记较准"作为分子**——主动标记者天然偏正向，存在自选择偏差，会系统性高估。**必须做随机抽样回访。**
  - 样本 N ≥ 100，窗口为内测期 14 天。
- **T02 钓位采纳率 ★**：分子为发生**导航跳转或收藏**行为的推荐条数；分母为**展示的推荐条数**（按条不按人）。样本 N ≥ 300 条展示记录。
- **T03 召回质量**：有效水域定义为**经人工核验可合法垂钓、且往返车程 ≤ 2 小时**的水域。测试口径：3 个试点城市（一线/二线/三四线各 1）**各取 5 个随机城区坐标点**分别评估后取中位数。
- **T11 成本**：必须输出 **用户量 → 日调用量 → 月成本（元）** 曲线，并按调用量预算给出绝对数（当前估算约 2.4 万次/日）。
- **T06/T07 稳定性**：T07 特别区分**未降级失败**与**降级后成功**——备源切换成功不应算失败，但必须记录降级率作为独立观察项。

### 9.4 上线门禁规则

**K01–K04 任一不达标 → 不得上线、不得进入下一阶段推进。**
门禁指标**不接受内测期豁免**：合规与隐私问题不会因为用户少而变小。

### 9.5 复盘与校准

- **M2 内测结束后复盘校准**，据实调整阈值；**调整必须留痕**（记录旧值、新值、调整理由），禁止事后静默改指标。
- **O 类指标是校准的燃料**：规则引擎的因子权重必须用 O01 与真实出钓反馈回溯拟合，而非长期停留在经验值。
- 指标达成但**假设被证伪**（如留存达标但付费意愿为零）时，以假设结论为准触发转向预案，**不得用指标达标掩盖方向错误**。
