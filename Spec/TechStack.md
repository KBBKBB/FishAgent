## 一、架构总览

```
┌─────────────────────────────┐
│   客户端（小程序 / H5 / App）  │   ← 不持有任何 Web 服务 Key
│  · 定位授权（wx.getLocation） │
│  · 展示结论与因子明细          │
│  · 埋点上报                   │
└──────────────┬──────────────┘
               │  HTTPS（仅业务请求，不含地图 Key）
┌──────────────▼──────────────┐
│      自建服务端（FastAPI）      │   ← 所有外部 API 调用的唯一出口
│  ┌────────────────────────┐ │
│  │ API 网关 / 鉴权 / 限流    │ │
│  ├────────────────────────┤ │
│  │ 坐标转换 wgs84_to_gcj02  │ │  【强制】统一入口
│  ├────────────────────────┤ │
│  │ 鱼情规则引擎 (F1–F7)      │ │
│  ├────────────────────────┤ │
│  │ 钓位召回 + 车程精算        │ │  两级过滤
│  ├────────────────────────┤ │
│  │ 禁钓过滤（门禁 K01/K02）   │ │  【强制】推荐前必过
│  ├────────────────────────┤ │
│  │ LLM 对话编排 (Agent)      │ │
│  └────────────────────────┘ │
└───┬──────────┬──────────┬───┘
    │          │          │
┌───▼───┐ ┌───▼────┐ ┌──▼─────┐
│ 高德   │ │Open-   │ │  LLM   │
│Web服务 │ │Meteo   │ │  API   │
└───────┘ └────────┘ └────────┘
    │          │
┌───▼──────────▼──────┐
│ PostgreSQL + PostGIS │  Redis 缓存
└─────────────────────┘
```

**核心架构原则**：客户端极薄，服务端厚。所有第三方调用、密钥、业务逻辑均在服务端。

> 依据 `Spec/Mission.md` v1.1 §四：M1 竞品实证显示「气压 + 鱼情预测」已被垂类 App 高使用率实现，
> 故**卖点优先级调整**，技术投入随之重新分配：

| 层级 | 能力 | 技术模块 | 投入策略 |
|---|---|---|---|
| **核心差异** | 往返 2h 车程精确可达性 | 钓位召回 + 网格分片 + 车程精算（§4.2） | **重点投入**，必须做到口径正确、可复现、可解释 |
| **核心差异** | 敢劝退 | 规则引擎分档（§4.1 factors）+ 强制提示 | **重点投入**，P1 原则不可弱化 |
| **次要强化** | 可解释性 | Top 3 因子明细输出 | 保持（P2 原则必交付项） |
| **基线（达标即可）** | 鱼情评分 / 气压分析 | Open-Meteo 接入 + 规则引擎（§4.1） | **达标即可**，不再作为竞争主张、不追加算法投入 |

> ⚠️ **不变项**：实现红线 R1–R8、性能/成本约束（§六）、合规要求（§五）**不因优先级调整而放宽**。

## 四、外部数据源

### 4.1 气象 / 气压

> **卖点定位（G1 调整）**：**基线功能**——达标即可，不作为竞争主张（见 §1.1、`Spec/Mission.md` §4.3）。
> 接口与取值约定（`pressure_msl`、F1/F2 口径）**保持不变**，但不追加算法/模型投入。

| 服务 | 用途 | 授权状态 |
|---|---|---|
| **Open-Meteo** | 主数据源。`pressure_msl`（海平面气压）、温度、湿度、降水、风速风向、云量、历史数据 | ⚠️ **免费层为 Non-Commercial（CC BY 4.0）**；商用需购买 API Key（`customer-` 前缀域名） |
| 和风天气 | 备源（国内访问快） | 商用需确认授权范围 |
| 心知天气 | 备源 | 商用需确认授权范围 |
| 中国气象数据网 CMA | 备用（门槛高） | 需注册 |

**关键取值约定【强制】**：
- 统一采用 **`pressure_msl`（海平面气压）**，不用 `surface_pressure`
  - 理由：海平面气压消除海拔差异，便于跨地区比较
- F1 因子必须计算 **24 小时变化量** + **3h/6h 短时变化率**
  - 理由：24h 差值天然抵消半日气压潮（日变化周期），但触发鱼口的关键信号常是 3~6h 内的快速变压
- F1 应**优先使用未来 24h 的预报变化量**
  - 理由：「气压即将骤降」的决策价值远高于「已经降了」
- F2 必须**相对当地近 30 天 `pressure_msl` 分布做归一化**，不得使用全国统一阈值
  - 理由：冬季平均气压显著高于夏季，固定阈值会造成系统性季节性误判

### 4.2 地图 / 水域 POI

> **卖点定位（G1 调整）**：**核心差异投资**——「往返 2h 车程精确可达性」是主打卖点（见 §1.1、
> `Spec/Mission.md` §4.1）。本模块的 POI 召回、网格分片与**车程精算（R4）** 须重点保障。

| 服务 | 用途 |
|---|---|
| **高德开放平台** | POI 搜索（周边 / 多边形 / 关键词）、路径规划、距离测量、地理/逆地理编码、坐标转换 |
| 腾讯位置服务 | 备选 |
| OpenStreetMap | 精细化水系数据（进阶） |

**用到的具体接口**：

| 接口 | 端点 | 用途 |
|---|---|---|
| 周边搜索 | `v3/place/around` | 钓位粗筛 |
| 多边形搜索 | `v3/place/polygon` | 突破半径上限的分片覆盖 |
| 关键字搜索 | `v3/place/text` | 水域名关键词召回（双路召回之一） |
| 驾车路径规划 | `v5/direction/driving`（或 v3） | 车程精算 |
| 距离测量 | `v3/distance`（`type=1`） | 批量车程精算 |
| 坐标转换 | `v3/assistant/coordinate/convert` | WGS84 → GCJ-02 |
| 逆地理编码 | `v3/geocode/regeo` | 位置描述 |

### 4.3 水文数据（进阶 / M5）

## 五、实现红线（【强制】项，违反即缺陷）

### R1 【强制】坐标系统一

- 手机 GPS / Open-Meteo → **WGS84**
- 高德所有 Web 服务 API → **GCJ-02**（仅接受 GCJ-02 输入）
- 境内偏差 **50~500 米**，可直接导致"推荐钓位落到对岸"
- **实现要求**：
  - 封装 `wgs84_to_gcj02()` / `gcj02_to_wgs84()` 为**唯一转换入口**
  - **禁止裸坐标直接进入地图 API**（代码评审检查项）
  - 天气查询继续使用 WGS84 原始坐标（Open-Meteo 不接受 GCJ-02）
  - 上线前用已知坐标点做**回归校验**

### R2 【强制】周边搜索半径硬校验

- `v3/place/around` 的 `radius` 取值范围 **0~50000 米**
- **超过 50000 按默认值处理（默认仅 3000 米），且不报错、静默降级**
- **实现要求**：
  - 代码层对 `radius` 做**硬校验 / 断言**，禁止 > 50000 的值进入请求
  - 对召回量设置**异常下限告警**（召回量骤降是最典型的故障信号）
  - 覆盖 50km 以上范围必须走网格分片或多边形分片

### R3 【强制】密钥不下发客户端

- 高德 **Web 服务 Key 严禁下发到客户端**，否则可被抓包窃取并刷爆配额
- **实现要求**：
  - 所有 Web 服务调用**经自建服务端中转**
  - 启用 **IP 白名单 + 数字签名（`sig`）**
  - Key 仅存于服务端密钥管理，**严禁写入任何前端产物**
  - 客户端只接收业务结果

### R4 【强制】车程精算口径

- **终点必须取 POI 入口坐标**：使用 `extensions=all` 返回的 **`entr_location`**
  - 理由：水库/湖泊 POI 中心点常落在水面上，会产生错误行程时长甚至不可达终点
  - 缺失时回退中心点，并**标记该候选"端点精度较低"**
- **往返口径不得用"单程 × 2"近似**：
  - 保留条件：`duration_去程 + duration_回程 ≤ 7200 秒`
  - 理由：忽略返程路况差异（早出晚归跨早晚高峰），会系统性低估实际往返时间
  - 实现：按方向各调用一次，或按方向分批
- **批量参数结构**：距离测量 API 是 **1 个终点 × 最多 100 个起点**（`origins` 以 `|` 分隔，上限 100）
  - 本场景用法：**以用户位置为唯一起点，多个候选水域作为终点合并请求**（注意方向与直觉相反）
  - 去程与回程各一次请求即可覆盖 100 个候选
- **口径策略**：**排序用基准路况、展示用实时路况**；结果页标注"预估"；记录本次计算的口径与时刻（供复盘与缓存复用）
  - 理由：实时路况口径的结果不可复现、不可缓存、跨时段漂移

### R5 【强制】禁钓过滤前置

- 推荐结果**必须经过禁钓过滤**，禁止输出：
  - 禁渔期内的天然水域（如长江流域十年禁渔）
  - 饮用水水源一级保护区
  - 私人承包塘 / 养殖区（未获许可）
  - 危险区域（高压线下、泄洪道、陡峭堤岸等）
- **高危类型必须接入权威矢量边界数据**，边界不明时**保守排除**（宁可不推荐）
  - 理由：人工维护名单不可能完整，若以此支撑漏出率为 0 的门禁指标，指标在设计上不可达成
- 过滤逻辑必须**在召回之后、返回之前**执行

### R6 【强制】AI 内容标识

- 产品内鱼情分析结论属 **AI 生成内容**
- 必须添加**显式标识**（用户可感知的提示，如"AI 生成 / 仅供参考"）与**隐式标识**（文件元数据）
- 依据：《人工智能生成合成内容标识办法》（2025-09-01 施行）

### R7 【强制】位置隐私

- 定位属敏感个人信息，遵循**"最小必要、用完即弃"**
- 避免长期明文存储精确位置
- UGC 钓点共享默认模糊化（**建议默认 500m 网格**）
- 需提供独立隐私政策与授权说明

### R8 【强制】不播报气象预报

- **只输出鱼情结论与因子解释，不原样播报气象预报**
- 确需展示数据时，标注数据来源与发布时间
- 不做"明日天气播报"式功能

## 六、性能与成本约束

### 6.1 性能目标（对应验收指标）

| 指标 | 目标 | 约束来源 |
|---|---|---|
| Agent 全链路 P95 | ≤ 5 秒 | T04 |
| 钓位推荐（含批量精算）P95 | ≤ 3 秒 | T05 |
| 核心链路可用性 | ≥ 99%（14 天） | T06 |
| 未降级失败率 | ≤ 0.5% | T07 |
| 单次对话 LLM 成本 | ≤ ¥0.05 | T12 |

**P95 定义**：服务端自收到请求到返回完整响应体的耗时，**不含客户端渲染与公网传输**；采样**同时包含成功与失败**请求。

### 6.2 调用量预算（日活 1,000 人 / 人均 3 次推荐）

| 环节 | 单次调用量 | 日调用量 | 优化手段 |
|---|---|---|---|
| 天气查询 | 1（可批量） | ~3,000 | 用户网格 + 60 分钟缓存 → 可降至数百 |
| 水域 POI 周边搜索 | **3~9（网格分片）** | **~15,000** | 受 ≤50km 硬上限约束必须分片；配网格缓存 + POI 去重可回落 |
| **距离 / 路径精算** | **2（去/回程各 1 次，每次 ≤100 终点）** | **~6,000** | 依赖批量优化，否则量级放大 20 倍以上 |
| 坐标转换 | 1 | ~3,000 | **客户端本地转换（纯算法）→ 降为 0** |
| **合计** | | **约 2.4 万次/日** | |

- 目标：各接口日调用量 **≤ 免费额度 70%**（T11，且必须给出绝对数）
- **风险**：若不批量、不缓存、不分片去重，可轻易突破 **十万级/日**
- **动作项**：M1 实测高德个人 Key 的实际日配额与**各接口独立配额**（POI 搜索与路径规划通常分属不同配额池），输出"配额 → 可支撑用户量"对照

### 6.3 缓存策略

| 数据 | TTL | 说明 |
|---|---|---|
| 气象数据 | 30~60 分钟 | 按用户所在网格聚合 |
| POI 搜索结果 | 网格级缓存 | 配合去重，显著降低分片开销 |
| 车程精算结果 | 基准口径可缓存 | 记录口径与时刻；实时口径不缓存 |
| 禁钓边界数据 | 长周期（日级刷新） | 变更低频 |
