## 1. 试点目的与判断问题

试点不是追求增长，而是验证「出钓前决策」是否真实可用、可信、可运营。需要回答四个问题：

| 编号 | 判断问题 | 对应证据 |
|---|---|---|
| Q1 | 推荐是否可信可用：水体是否正确、车程是否真实、禁钓是否排除、导航能否落地 | Top5 人工抽检、用户反馈、导航点击与到达自报 |
| Q2 | 用户能否在可接受时间内拿到结论 | 鱼情/钓位/Agent 三段耗时与错误率 |
| Q3 | 安全合规提示是否被看见并影响决策 | 强制提示曝光、劝退场景反馈、合规抽检 |
| Q4 | 是否具备继续、调整或停止的条件 | §6 停止条件与 §7 准入条件 |

**试点假设（需验证，不作为事实）：**
- H1：钓友愿意用「分数 + 理由 + 时段」替代自己看气压/天气。
- H2：2 小时车程内的真实水体推荐，比「附近渔具店/宽泛地图搜索」更有决策价值。
- H3：强制安全提示不会显著降低使用意愿，反而提升信任。
- H4：20–30 秒的钓位规划耗时可被接受，但需要明确进度提示。

## 2. 目标用户与场景

### 2.1 目标用户

- 成都主城及近郊（含郊区）的休闲钓友，以周末/清晨出钓为主，单程可接受约 1 小时、上限 2 小时；默认起点为成都天府广场（30.6570, 104.0660）。
- 使用手机浏览器（H5），习惯看天气、气压、风向后再决定是否出钓。
- 关注「去哪、几点去、今天值不值得去」，不要求特定鱼种或渔获保证。

### 2.2 核心场景

1. **出钓前一天晚上**：判断明天是否值得安排，偏好时段是什么。
2. **当天清晨**：临时确认天气与窗口，决定就近或按推荐出发。
3. **临时换点**：原钓点不合适时，寻找 2 小时车程内可替代的真实水体。

### 2.3 非目标用户与场景

- 海钓、船钓、竞技黑坑、商业塘、养殖场等需要专门信息的场景。
- 需要「保证有鱼/保证爆护」或精确到钓位的用户。
- 成都及郊区以外城市、离线环境、需要账号体系或社区内容的行为。
- 以渔获交易、钓场预订、直播为目的的使用。

### 2.4 产品价值主张

把气压、风、降水、温度转成**可解释的鱼情结论**，叠加**2 小时车程内的真实自然水体**、**最佳窗口**与**恶劣天气劝退**，帮助用户在做决定前少查几个 App、少跑冤枉路。

## 3. 试点边界

| 项 | 试点口径 |
|---|---|
| 城市 | 仅成都及郊区（主城 + 近郊）；其他城市不承诺召回质量 |
| 默认起点 | 成都天府广场（30.6570, 104.0660）；用户可手动改坐标 |
| 端 | 仅 H5；不发布小程序、不做 App |
| 数据源 | 真实高德 / Open-Meteo / DeepSeek；Mock 仅用于演示与回归，不进入试点用户路径 |
| 默认半径 | 默认 50km；100km 作为可选项并展示「未评估 N」。理由见 §3.1 |
| 导航 | 允许 `center_fallback`，但必须显示「端点精度较低」；不承诺精确岸边/下水点 |
| 车程 | 展示「预估车程，实际以导航为准」；回程为近似口径，不承诺到达时间 |
| 账号与数据 | 无账号、无 UGC、无支付；不持久化精确位置；日志脱敏 |
| 对外口径 | 封闭邀请制体验，不对外发布、不投放、不宣传「保证渔获」 |

### 3.1 成都校准判断与默认 50km 理由

**是否需要成都专属校准：需要“本地化修补”，暂不需要重做鱼情评分规则。**

- 不需要重做 F1–F7：规则输入为气压、风、降水、温度等天气量，与城市无关；成都单点抽检鱼情 85 分/极佳、窗口正常，说明链路可用。
- 必须本地化修补：
  1. **水体召回排除规则（P0，已修复）**：成都抽检 Top5 曾出现「碗山河·西南风味菜·现炒浇头面(水璟唐店)」。高德原始数据将该餐饮 POI 标为 `190204`，同坐标另有 `050000` 餐饮 POI，原 typecode 过滤无法识别；已增加“水体类型 + 经营名称/业态”保守排除并补回归测试（小钱，R3）。
  2. **禁钓边界（D11，工程已关闭）**：人类已授权“暂无名单，暂定除国家公园等保护地外全部水域可钓”。工程为默认允许所有水体；仅当名称命中 20 个保护地/禁钓/水源/军事等关键词，或位于已配置禁钓圆区时排除；新增 8 个保护地关键词与 28 条测试，126 passed。名称过滤为启发式，非权威边界；页面保留“是否可钓以当地公告为准”，不承诺禁钓完整性。
  3. **默认参数**：默认起点成都天府广场；默认半径 50km；100km 可选并展示未评估数。
- P0 修复后复核成都 50/100km：工程复核 Top5 已全为自然水体，50km 13.92s、100km 18.71s；小测 v1.4 独立复验 50km 14.652s、100km 26.150s，Top5 全为自然水体，三条不变式与往返 ≤7200s 均成立，H5 34/34，P0/P1/P2=0/0/0。工程/合规阻塞已关闭，S1 已于 2026-10-22 放行；S1 期间义务见 §11。

**默认 50km 的理由（基于 2026-10-22 抽检）：**

| 维度 | 50km | 100km | 结论 |
|---|---|---|---|
| 实测耗时 | 16.45s | 19.35s / 33.33s（两次） | 50km 更稳，100km 尾部超 30s Gate |
| Top5 结果 | 锦江、府河、碗山河（餐厅，修复前样本）、锦江、东湖 | 与 50km 同量级且未评估 640 | 半径扩大未带来明显更好的结果，反而增加等待与解释成本 |
| 未评估数 | 较少 | 640（超出本轮预算） | 需展示「未评估 N」，用户理解成本高 |
| 结论 | **试点默认** | 可选，显示未评估与更慢提示 | 先以 50km 建立信任，再按反馈开放 100km |

> 说明：上表为 P0 修复前的抽检基线，用于比较半径策略；修复后工程复核与两轮独立复验的 50/100km Top5 均已全为自然水体。成都抽检仍为单点、单实例、单时段样本，不代表全成都；S1 已放行，按放行口径定向邀请，单点样本不足的部分由 S1 期抽检与用户反馈补充。

## 4. 成功指标

> 指标分为「硬门槛（Gate）」与「学习指标（Learning）」。阈值已由人类确认（D7）；首期学习指标先建立基线，不因未达阈值直接判失败。

### 4.1 推荐可用性

| 指标 | 定义 | 建议阈值 | 类型 | 数据来源 |
|---|---|---|---|---|
| Top5 水体正确率 | 返回的钓位中自然水体（河流/湖泊/水库）占比 | 100% | Gate | 每会话 Top5 人工抽检 + 名称/类型 |
| 约束合规率 | 往返 ≤7200s、命中 D11 规则的钓位已排除、去重、≤limit | 100% | Gate | 自动断言 + 抽检 |
| 导航可落地率 | 点击导航的用户中，自报「能到达可作钓岸线/入口」的比例 | ≥80% | Learning | 会话后问卷 |
| 鱼情可解释率 | 7 因子和=总分、Top3 存在、窗口数量符合档位 | 100% | Gate | 自动化回归 |
| 推荐采用率 | 有钓位结果的会话中，至少点击 1 次导航的比例 | 首期基线 | Learning | 前端埋点或日志 |
| 有效推荐率 | 有钓位结果的会话 / 发起钓位请求的会话 | ≥90% | Learning | 服务端日志（空态、超时分开统计） |

> 注：成都「禁钓排除」按 D11 口径（默认允许，保护地/水源/军事等名称关键词 + 已配置禁钓圆区）核验，属启发式过滤，不是权威边界，不能对外承诺全量禁钓覆盖；`forbidden=0` 仅表示未命中规则，不等于“均可钓”。页面与文档须保留“是否可钓以当地公告为准”。

## 5. 反馈采集方式

### 5.1 渠道组合

1. **内测群（即时）**：用户随时反馈；按固定模板收集「时间、位置、问句/页面、截图、期望 vs 实际」。
2. **会话后问卷（主渠道）**：3 题、30 秒内完成，建议外链问卷，不新增后端。
   - Q1 这次推荐对你有用吗？（1–5）
   - Q2 你会按推荐出钓/已经出钓吗？（会 / 不会 / 不确定）
   - Q3 最影响你决策的问题是什么？（水体不对 / 太远 / 导航到不了 / 鱼情不准 / 太慢 / 安全提示不清 / 其他 + 文本）
3. **可选访谈**：对人类确认后的志愿者进行短访谈；需单独授权，不强制。
4. **被动数据**：请求耗时、错误码、`filtered` 计数、`entry_precision`、导航点击、会话结果；不记录精确经纬度明文。

### 5.2 反馈标签与处置

| 标签 | 示例 | 默认级别 | 处置 |
|---|---|---|---|
| 安全/合规 | 暴雨未劝退、强制提示缺失、禁钓点返回 | P0 | 立即停止试点相关能力，修复并复验 |
| 水体错误 | 餐饮/小区/道路被当作钓位 | P0 | 立即暂停钓位推荐，修复召回 |
| 导航不可用 | 终点在水中央、无法到达岸线 | P1 | 评估入口坐标方案；必要时降级文案 |
| 性能 | >60s、超时、长时间无进度 | P1 | 限流/并发/半径策略调整 |
| 鱼情不符 | 分数与体感差异大 | P1 | 收集样本，规则校准（F5 临时口径） |
| 展示/文案 | 字段缺失、错别字、移动端溢出 | P2 | 排期修复 |
| 需求建议 | 新鱼种、新城市、收藏等 | Backlog | 不进入本轮试点范围 |

### 5.3 隐私与授权

- 问卷与访谈前提供用途说明；用户可拒绝或随时退出。
- 截图与位置信息由用户自愿提供；群内不要求发送精确坐标，可用大致区域替代。
- 不在试点中新增持久化精确位置；服务端日志继续脱敏。

## 6. 停止与暂停条件

### 6.1 立即停止（P0）

任一条发生即暂停试点相关能力，修复并复验后再恢复：

1. 返回命中 D11 规则（保护地/水源/军事等名称或禁钓圆区）的钓位；经核实的保护地/禁钓水体未被 D11 规则排除；往返 >2h 的钓位；或 Top5 出现餐饮/住宅/学校/道路等非水体（含成都「碗山河·西南风味菜」这类被高德标为 `190204` 的餐饮 POI）。
2. 暴雨/雷雨、≥5 级风、骤降 >8hPa/24h 的强制提示缺失、降级或被裁剪。
3. `band=劝退` 未给出「今天不建议出钓」，或仍展示出钓窗口。
4. Key 泄露到前端/日志/仓库；出现第三方直连；精确位置被持久化。
5. 接口返回 5xx 堆栈，或安全/合规文案缺失。
6. 用户报告导航终点存在明确人身安全风险（如进入水域中心、封闭危险区域），经核实后立即停用该点导航。

### 6.2 暂停并修复（P1）

| 条件 | 建议动作 |
|---|---|
| 钓位 P95 >60s 连续 3 天，或 Agent 钓位超时率 >10% | 保持默认 50km；检查配额/并发；必要时限流并复测 |
| 100km 连续 3 次 >30s（如成都抽检 33.33s） | 默认半径保持 50km；100km 加显著耗时提示；必要时限流或暂时隐藏 100km |
| D11 名称规则出现可复现漏排/误排 | 补充关键词与回归，复验后再扩大范围 |
| API 错误率 >5%（一个复盘周期） | 停止扩大邀请；定位 Provider/超时/配额 |
| 同一区域 ≥2 位用户独立报告「导航到不了」 | 评估入口坐标方案；未修复前对该类点位加显著提示 |
| ≥30% 反馈用户有用性 ≤2 分（一个复盘周期） | 暂停新增用户；复盘推荐质量与期望管理 |
| 「明早」类问句错误进入 Top2 问题 | 优先修复相对日期解析（M3），再继续 |
| `unevaluated` 未展示导致用户误解 100km 结果 | 先修展示或默认 50km |
