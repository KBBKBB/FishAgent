# FishAgent MVP 交付计划

> 版本：v1.0 ｜ 编制：小项 ｜ 日期：2026-10-21
> 依据：`README.md`、`项目立项文档.md`、`Spec/Mission.md`、`Spec/TechStack.md`、`Spec/Roadmap.md`

## 一、目标

把现有「只有立项与 Spec 文档」的仓库推进为**可运行的 FishAgent MVP**：用户输入位置后，获得鱼口活跃度评分与可解释因子、2 小时往返车程内的钓位推荐，并可通过自然语言对话获得整合结论。Agent 层使用成熟框架（LangGraph），不自研编排内核。

**本轮成功标准**：Mock 模式无需任何外部 Key 即可启动并完成演示，自动化测试通过，交付运行说明与验收报告。

## 二、范围

### 2.1 本轮范围内（MVP）

| 能力 | 说明 |
|---|---|
| 鱼情分析 | F1–F7 规则引擎、0–100 评分、五档结论、Top 3 因子解释、最佳时段/水深/鱼种建议 |
| 钓位推荐 | 水域 POI 召回（Mock + 高德适配器）、入口坐标、往返车程分别计算与 ≤7200s 过滤、禁钓保守过滤、综合排序 |
| 自然对话 Agent | LangGraph 编排 + 工具调用（鱼情/钓位），无 LLM Key 时使用确定性兜底路由 |
| H5 演示界面 | 定位/手动坐标输入、评分卡与因子明细、钓位列表、对话入口、AI 标识与免责声明 |

- 高德/Open-Meteo 真实 Key 的配额实测与生产部署

- A2：H5 采用静态页面（无构建链），由 FastAPI 同源托管，降低 MVP 环境依赖。
- A3：成员在同一仓库工作，按目录划分所有权，避免并发冲突。

## 四、验收标准（本轮 DoD）

1. 无外部 Key 的 Mock 模式下，后端启动成功，`/health`、`/api/fish-activity`、`/api/spots/recommend`、`/api/agent/chat` 均返回契约内响应。
2. 规则引擎输出 7 个因子得分、总分 0–100、五档映射正确（40/55/70/85 边界），Top 3 因子与明细一致；暴雨/≥5 级风/骤降触发强制提示。
3. 钓位推荐满足：单次 `radius ≤ 50000m` 硬校验；去/回程分别计算且合计 >7200s 被过滤；优先 `entr_location`，缺失时回退中心点并标记；禁钓候选被排除。
4. Agent 对「今天气压适合钓鱼吗」「附近哪里野钓好」「明早几点去最好」三类问句给出正确工具调用与建议；无 LLM Key 时 fallback 可用。
5. H5 页面在 `http://127.0.0.1:8000/` 可完成「输入位置 → 查看评分与因子 → 查看钓位 → 对话」全流程，并展示 AI 标识与免责声明。
6. `python -m pytest` 全部通过；`ruff check .` 无错误（允许明确记录的忽略项）。
7. 交付文档：PRD、API 契约、测试报告、验收报告、README 快速开始；仓库中无任何真实密钥。
